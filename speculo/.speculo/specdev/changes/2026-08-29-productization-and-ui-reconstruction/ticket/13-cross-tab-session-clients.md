## 1. 战略与来源

- **目标：** 正确消费 heartbeat/renew/stable CSRF，并在多标签中协调客户端活动而不把频道当作授权事实。
- **可观察产出：** 单标签发起有界 heartbeat/renew；登录/退出/撤销提示同步；并行写使用同一稳定 CSRF。
- **来源：** `US-005~006`、`AC-011`、`AC-013`、`ADR-006`。
- **当前事实：** browser session fetch 串行单页请求但没有跨标签协议；Desktop 使用独立 vault adapter。
- **Planning Depth 原因：** 客户端竞态可能放大数据库写入或错误复活已撤销 Session。

## 2. 决策状态

### 已锁定决策

- BroadcastChannel 只同步状态和协调，不作为认证/授权事实源。
- Current 只读；heartbeat/renew 受 CSRF 保护且有界；退出/撤销以服务端响应为准。
- Web 共享 Cookie；Desktop 继续由原生 vault/session client 持有 secret。

### 已采用的低影响假设

- 多标签协调使用 leader lease + 可恢复超时；无 BroadcastChannel 时各标签使用更保守的有界策略。

### 已批准偏差

- **DEV-13-001（USER-DECISION:all-approved）：** T-13 可临时写入上述六类 Tauri host 路径，仅新增 `desktop_session_heartbeat` / `desktop_session_renew` 专用命令及其最小 manifest/permission 注册。Rust 必须在 vault 内消费、校验并提交 cookie/CSRF rotation，返回 JS 的值只能是严格校验后的 `PublicProfile`；通用 `desktop_request` 不得承载 Session maintenance，vault 布局与其他 host 能力保持不变。

### 未决问题

无。

## 4. 要构建什么

Session controller 根据实际用户活动安排 heartbeat，并仅在续期窗口请求 renew。浏览器标签通过频道选出当前协调者并广播非敏感状态版本；任何标签收到 401/撤销都重新读取服务端事实并停止心跳。Desktop 使用相同 domain state，但 token 继续留在原生宿主。

## 5. 实现契约

- **入口或接缝：** session controller、browser fetch/coordinator、desktop session adapter。
- **输入与输出：** generated Session DTO/Problems、visibility/activity、non-secret channel messages。
- **公共接口变化：** 前端 adapter/domain API 演进；后端合同不变。
- **不变量：** 频道不携带 token/CSRF；无客户端消息可建立认证；timer 有界且可清理。
- **状态或数据流：** server current -> controller -> leader scheduler -> heartbeat/renew -> broadcast version。
- **错误与失败行为：** 401/403/429、后台标签、频道丢失、leader 崩溃均可恢复且不循环请求。
- **兼容要求：** 删除 rotate-on-every-response 客户端假设。
- **安全与隐私要求：** 消息只含事件类型/版本/时间桶，不含身份详情或 secret。
