## 1. 实现摘要

- API 使用 Go 1.26.5 多阶段静态构建和 Alpine 非 root UID 10001 运行镜像；Web 使用 Node 22.22.3/pnpm 11.1.3 构建、Nginx 1.29.8 UID 101 只读运行。
- 生产 Compose 编排 PostgreSQL 17.11、Redis 8.10、一次性 migrate、API 和唯一宿主入口 Web；PostgreSQL/Redis/FileStore 使用持久卷，API 默认不发布宿主端口。
- `postgres/redis healthy -> migrate success -> api ready -> web` 使用条件依赖和 healthcheck；迁移非零退出阻止 API，依赖中断使 readiness 返回 503。
- Nginx 同源代理 `/api`、`/login`、`/static`，保留 SPA 深链，同时保证后端 404 不被替换为 SPA 200。
- runtime config、PostgreSQL 密码和 JWT secret 在部署时生成；容器 read-only、非 privileged、drop all capabilities，应用镜像不包含演示配置或数据库。
- 生产验证码登录 E2E 生成真实挑战并通过受控 Redis 测试接缝提交答案；验证码答案不写测试日志，后端同时删除了既有明文答案 info 日志。
- Linux `os.Root.MkdirAll` 的 symlink parent `EEXIST` 被归一化为既有 `ErrInvalidFileKey`，保持跨平台 FileStore escape 合同。
- release workflow 固定 root/backend/frontend SHA，生成 linux/amd64 镜像 tar、Compose bundle、digest、SPDX JSON SBOM、manifest 和 `SHA256SUMS`。
